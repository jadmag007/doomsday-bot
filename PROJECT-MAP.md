# PROJECT-MAP — Doomsday Tyranny bot (для любого агента)

Дата: 2026-09-17 (после ревизии workspace). Версия: **2.5.1** (main = 4a7ce0b).
Репо на GitHub: https://github.com/jadmag007/doomsday-bot (приватное, юзер jadmag007).

## ГЛАВНОЕ: работа агентов через GitHub

- В репо две ветки:
  - **`main`** — чистый код бота (его тянет устройство, не засорять);
  - **`workspace`** — рабочее место агента = main + рабочие папки:
    `research/`, `scripts/`, `upload/`, `logs-archive/`, `PROJECT-MAP.md`,
    `MANIFEST.md`, `worklog.md`.
- **Онбординг нового агента**: владелец выдаёт PAT (read/write на это репо) →
  клонировать ветку `workspace` → прочитать `PROJECT-MAP.md` и `worklog.md` →
  работать → коммитить и пушить в `workspace`.
- **PAT НИКОГДА не кладётся в репо** — это ключ от него же. Утёкший токен =
  полный доступ. Перед каждым пушем — скан на строку токена (встроен в
  `release.sh` и `push_workspace_branch.sh`).
- **Релиз в main**: `bash scripts/release.sh <версия> "<описание>"` —
  тест панели → бамп VERSION → клон main → синк dev-дерева (вкл. удаления) →
  selftest → скан утечек → пуш. Устройство подхватит `git pull` / `doomsday start`.

## Ключевые факты об архитектуре (v2.5.x)

- Бот: Python-воркер + cronie-обёртка + web-панель (порт 8080).
- Установка: git-клон + `install.sh` (Termux, Android). Zip-обновлятор удалён в v2.0.0.
- Ребут по концу цикла: `_cycle_end_watch_due` ловит конец цикла за 2 мин до и
  до 30 мин после, цикл проверки 30 с; троттлинг ошибок 2 мин; резервные проходы
  помечаются `[fallback]` в cron.log; анти-шторм спавнов 1/мин.
- Планировщик на устройстве ненадёжен (Android морозит Termux/cronie) — поэтому
  в панели есть резервный планировщик.

## Грабли (уже наступленные — не повторять)

- PAT раньше терялся при сбросах песочницы → теперь трекается локальным git
  песочницы. Никогда не писать значение токена в worklog/файлы репо. В старом
  `push_130_github.sh` токен был захардкожен — вычищен при ревизии 2026-09-17.
- После каждого крупного шага — commit в git песочницы (сбросы откатывают
  дерево к последнему автосейву).
- rsync с конечным слэшем у источника-каталога вываливает содержимое в цель —
  первая версия ветки workspace так была испорчена (все папки в корне).
  Правильно: `rsync -a "$SRC/" "$DST/subdir/"` с явным путём назначения.
- В пуш v2.5.1 случайно попали мёртвые `lib/updater.py` + `update.sh` — всегда
  сверять состав коммита (в release.sh теперь синк удалений).
