# ☢ Doomsday Tyranny Bot (Termux)

Автоматизация игры **DoomsDay Tyranny** (Telegram Mini App, бот [@DoomsDayTyrannybot](https://t.me/DoomsDayTyrannybot)) на Android через Termux.

Возможности:
- **Ребут производства каждые 12 часов** (Premium-цикл) — автоматически, по расписанию;
- **Скан ресурсов каждый час** — контроль переполнения склада («Склад переполнен», «Требуется перезагрузка», «Перегрев» и др.) с push-уведомлениями;
- **Мониторинг уведомлений бота** в чате (catch-up при каждом скане);
- **Веб-панель** на телефоне (`http://127.0.0.1:8080`): таймеры с обратным отсчётом, ресурсы, все настройки, журнал, ручные действия;
- **Ежедневная сводка** и отчёты о ребуте;
- **Автоустановка** одним скриптом и **автообновление** из архива в Загрузках телефона.

---

## 1. Что нужно заранее

| Компонент | Откуда | Зачем |
|---|---|---|
| Termux | **F-Droid** или GitHub (НЕ Play Market — устарел) | терминал |
| Termux:API | **тот же источник**, что и Termux | push-уведомления |
| Termux:Boot | тот же источник | автозапуск после перезагрузки |
| api_id + api_hash | [my.telegram.org](https://my.telegram.org) → API development tools | вход вашим аккаунтом (Telethon) |

> Аккаунт управляется вашим собственным входом (MTProto user-клиент). Данные (api_hash, сессия, конфиг) хранятся **только на телефоне** в `~/doomsday-bot` с правами 600/700.

## 2. Установка

1. Скачайте архив `doomsday-bot-v*.zip` в **Загрузки** телефона.
2. Откройте **Termux** и выполните:

```bash
termux-setup-storage        # разрешить доступ к памяти (один раз)
pkg install -y unzip
unzip /storage/emulated/0/Download/doomsday-bot-v1.0.2.zip -d ~/doomsday-src
bash ~/doomsday-src/install.sh
```

Установщик сам: поставит пакеты (python, cronie, termux-api, termux-services), скопирует код в `~/doomsday-bot`, создаст venv с Telethon, проведёт мастер настройки (api_id/api_hash, телефон, интервалы), зарегистрирует cron (каждые 10 минут), сервис веб-панели и автозагрузку.

3. После установки:

```bash
doomsday login       # вход в Telegram: телефон → код → 2FA-пароль
doomsday check       # диагностика всех компонентов
doomsday discover    # поиск API игры (см. раздел 5)
```

> Команда `doomsday` после установки доступна из любого места Termux (симлинк в `$PREFIX/bin`).

## 3. Обязательные настройки Android

Иначе Android усыпит Termux и ночные проходы cron пропадут:

1. **Настройки → Приложения → Termux → Батарея → «Без ограничений»** (Unrestricted);
2. Зафиксируйте Termux в списке недавних приложений (не смахивайте из памяти);
3. (Android 12+, опционально) отключите phantom process killer:
   `adb shell "settings put global settings_enable_monitor_phantom_procs false"`
   или через device_config (см. вики Termux);
4. Установите **Termux:Boot** и один раз откройте его — подробности в разделе 3а.

## 3а. Активация Termux:Boot (автозапуск после перезагрузки)

1. Установите приложение **Termux:Boot** — APK с F-Droid или GitHub-releases
   Termux. ВАЖНО: источник должен совпадать с источником самого Termux
   (оба F-Droid или оба GitHub), иначе Android не даст им общаться.
2. **Откройте Termux:Boot один раз** — при первом запуске он инициализируется
   и запросит разрешения (Autostart/Notifications). После этого просто закройте.
3. Положите boot-скрипт (установщик делает это сам, но можно и вручную):

```bash
mkdir -p ~/.termux/boot
cp ~/doomsday-bot/boot/doomsday-boot.sh ~/.termux/boot/90-doomsday-boot.sh
chmod +x ~/.termux/boot/90-doomsday-boot.sh
```

4. Перезагрузите телефон для проверки: Termux мелькнёт в фоне, wake-lock
   возьмётся, сервисы поднимутся, и в журнале появится загрузочный проход
   (`doomsday log`).

## 4. Как это работает

```
cronie (каждые 10 мин) → doomsday cron
    ├─ автообновление: ищет doomsday-bot-v*.zip в Загрузках (раз в час)
    ├─ ребут: раз в 12 ч → Telethon → /start боту → Mini App API (шаги tma.steps_reboot)
    ├─ скан: раз в 1 ч → чат бота (catch-up) + API состояние (tma.steps_scan)
    │    └─ пороги: 90% предупреждение, 100% «Склад переполнен» → termux-notification
    └─ сводка дня в 20:00
doomsday-web (termux-service, резидентно) → веб-панель на 127.0.0.1:8080
```

Игра — Telegram Mini App: Telegram отдаёт URL приложения с авторизационными
данными только через MTProto. Поэтому движок через **Telethon** запрашивает
webview-URL (`RequestAppWebView`, short name `play`) и выполняет HTTP-шаги к API
игры с этой авторизацией. Пока шаги не настроены, работает «страховочный режим»:
в назначенное время придёт уведомление с кнопкой **«Открыть игру»** — вы
перезапускаете производство в два тапа вручную.

## 5. Автоматический ребут (TMA API) — уже встроен

Начиная с v1.3.0 точные шаги API игры **встроены в бота** (пресет «Doomsday
Firebase callable»): ничего настраивать не нужно. Протокол (реверс-инжиниринг
web-приложения игры): каждый вызов — POST на
`https://us-central1-telegram-miracle-f1779.cloudfunctions.net/<функция>` с телом
`{"data": {…аргументы, auth, session}}`, где `auth` — сырая строка tgWebAppData,
а `session` — поле hash из неё. Бот сам получает свежую подпись через Telethon
и вызывает:

- **reboot** → функция `rebootProduction` (без аргументов) — ответ содержит
  `{active, startedAt, endsAt}`: бот сохраняет дедлайн цикла, и в панели/сводке
  виден обратный отсчёт;
- **scan** → функция `initUser` — полное состояние игры: склады всех шахт,
  паузы/дефициты/перегрузки + дедлайн цикла. Состояния считаются той же логикой,
  что и в интерфейсе игры (простаивает / требуется ребут / пауза / дефицит /
  склад переполнен).

Если игра сменит сервер, `doomsday discover` найдёт её Firebase-конфиг в
JS-бандле, проверит рабочий эндпоинт синхронизацией времени `/syncTime` и сам
обновит `tma.base_url` в настройках.

Кастомизация (не обязательна): на вкладке **API / Discovery** можно задать свои
`steps_reboot`/`steps_scan` — они переопределят пресет. Доступные переменные:
`{{init_data}}`, `{{session_hash}}`, `{{base_url}}`, плюс `extract` — извлечение
значений из JSON-ответа по путям. Пример шага:

```json
[
  { "name": "rebootProduction", "method": "POST",
    "url": "{{base_url}}/rebootProduction",
    "body": { "data": { "auth": "{{init_data}}", "session": "{{session_hash}}" } },
    "extract": { "reboot_ends_at": "result.endsAt" } }
]
```

Для скана — аналогично (в пресете: `initUser` → полный стейт игры).

## 6. Веб-панель

- **Дашборд** — обратный отсчёт до ребута/скана, ресурсы с прогресс-барами,
  последние события, быстрые действия;
- **Таймеры** — интервал ребута (ч), скана (мин), время сводки, апдейтер;
- **Настройки** — Telegram (api_id/api_hash с маскировкой), мониторинг чата
  (паттерны уведомлений бота), события push-уведомлений, адрес/PIN панели;
- **API / Discovery** — запуск discovery, редактор HTTP-шагов, извлечение
  ресурсов, параметры обновлений;
- **Журнал** — события, запуски с логами, bot.log.

Доступ из браузера на телефоне: `http://127.0.0.1:8080`. Хотите со компьютера в
той же Wi-Fi сети — поставьте host `0.0.0.0` и задайте PIN (обязательно!).

## 7. Обновления

- Обновление распространяется тем же архивом: `doomsday-bot-v1.1.0.zip` → в Загрузки.
- Проверка — раз в час (и при каждом проходе cron при устаревшей проверке),
  кнопкой «Проверить обновления» или `doomsday update` (с `--force` — поставить даже ту же версию).
- Что делает апдейтер: валидирует архив (VERSION/lib), бэкапит текущий код в
  `.backup/`, заменяет только код (config.json, state.db, logs, session, venv — не трогаются),
  мигрирует конфиг, при изменении requirements.txt переустанавливает зависимости,
  перезапускает веб-панель и присылает уведомление. Применённые архивы
  запоминаются по sha256 и переносится в `~/doomsday-bot/.updates/`.
- Откат: `bash ~/doomsday-bot/.backup/<время>/… ` — просто переустановите старую
  версию архивом с `--force`.

## 10. Частые проблемы

| Симптом | Решение |
|---|---|
| Нет уведомлений | Приложение Termux:API не установлено / из другого источника, чем Termux. Проверка: `doomsday test-notify` |
| Ночные пропуски | Батарея Termux «Без ограничений» + Termux:Boot + не смахивайте Termux |
| «Сессия не авторизована» | `doomsday login` (сессия слетает при смене устройства/пароля) |
| FloodWait / лимиты | Не уменьшайте интервалы ниже разумных; скан ≥ 30 мин, ребут = 12 ч — норма |
| Сайт/бот недоступны | Техработы игры — ошибки придут уведомлением, повтор каждые retry_failed_minutes |
| Веб-панель не открывается | `sv up doomsday-web`, смотрите `~/.termux/... /log` или `doomsday web` в консоли |

## 11. Важно

- Инструмент управляет **вашим аккаунтом** и **вашей** игрой: держите интервалы
  мягкими (скан 30–60 мин), чтобы не создавать лишнюю нагрузку и не попасть под
  лимиты Telegram/игры. Автоматизация может нарушать правила игры — используете
  на свой риск.
- Весь трафик идёт напрямую: Telegram (MTProto) и серверы игры. Никуда ещё
  ничего не отправляется.

Версия: см. `VERSION`. Обновления — архивом `doomsday-bot-v<semver>.zip`.

## 12. Приватный репозиторий GitHub (синхронизация устройств)

Настройки и код можно держать в **приватном** репозитории — чтобы ставить и
тестировать на нескольких устройствах без ручного переноса.

**ВАЖНО (безопасность):**
- `config.json` коммитится сознательно — в нём api_id/api_hash и телефон.
  Репозиторий обязан быть **PRIVATE**. Не делайте его публичным, не форкайте открыто.
- `session/` (Telegram-сессия) **никогда** не попадает в git (.gitignore).
  На каждом устройстве — своя сессия: там всегда выполняйте `doomsday login`.
  Один и тот же файл сессии на двух устройствах одновременно — конфликты
  подключения и риск блокировки Telegram.

### Первый запуск (основное устройство)

```bash
pkg install -y git
cd ~/doomsday-src                        # исходники после unzip
# занести текущие настройки в репозиторий:
cp ~/doomsday-bot/config.json .

# создать ПРИВАТНЫЙ репозиторий на github.com (web), затем:
git init -b main
git add .
git commit -m "doomsday-bot v$(cat VERSION)"
git remote add origin git@github.com:ВАШ_ЛОГИН/doomsday-bot.git
# или HTTPS: https://github.com/ВАШ_ЛОГИН/doomsday-bot.git
git push -u origin main
```

Аутентификация с телефона проще всего через официальное CLI:
`pkg install gh && gh auth login` (спросит токен/браузер) — после него git
запускается без отдельного ввода паролей.

### Новое устройство

```bash
pkg install -y git unzip
termux-setup-storage
git clone git@github.com:ВАШ_ЛОГИН/doomsday-bot.git ~/doomsday-src
bash ~/doomsday-src/install.sh     # увидит config.json — мастер настройки пропустится
doomsday login                     # своя сессия для этого устройства
doomsday check
```

Альтернатива без отдельного каталога — клон сразу в место установки
(установщик это распознаёт и не копирует «в самого себя»):

```bash
git clone git@github.com:ВАШ_ЛОГИН/doomsday-bot.git ~/doomsday-bot
bash ~/doomsday-bot/install.sh
```

### Обновление кода на устройстве (git-путь)

Всё сразу делает стартёр — обновление из GitHub + переустановка + сервисы:

```bash
doomsday start            # или: sh ~/doomsday-bot/start.sh
```

Его же запускает Termux:Boot после перезагрузки телефона (раздел 3а),
так что вручную запускать не обязательно.

По шагам вручную (эквивалент):

```bash
cd ~/doomsday-src
git pull
bash install.sh                    # переустановка поверх: config/state сохраняются
```

Git-путь и zip-автообновление независимы: можно пользоваться любым (архив в
Загрузках по-прежнему подхватывается автоматически раз в час).

### Логи: буфер для передачи разработчику

`~/doomsday-bot/logs/` и `~/doomsday-bot/reports/` **никогда не
синхронизируются** с git (в .gitignore) — это локальный буфер устройства.
Когда нужно передать логи ассистенту (диагностика, баг-репорт):

```bash
doomsday logs-push       # соберёт логи+отчёты+метаданные и запушит
```

Как это устроено:

- бандл собирается во временный `~/doomsday-src/logsbuf/` (тоже не
  синхронизируется) и уходит в **отдельную ветку `logs`** репозитория —
  ветка `main` остаётся чистой, код с логами не смешивается;
- после успешной отправки локальная копия бандла удаляется — буфер чист;
- при ошибке сети бандл сохраняется на диске и попытку можно повторить;
- в бандл входят: хвосты логов (по 2000 строк), последние 50 отчётов,
  config.json (репозиторий PRIVATE — осознанно) и метаданные (версия,
  коммит, платформа).

Ассистент читает ветку `logs` и разбирает присланные данные.

### git без пароля (нужен для start и logs-push)

Чтобы `doomsday start` (git pull) и `doomsday logs-push` (git push) работали
без интерактивного ввода пароля, один раз сохраните токен:

```bash
doomsday git-auth
# спросит PAT со скрытым вводом; или: doomsday git-auth --token github_pat_...
```

Токен пишется в `~/.git-credentials` (права 600, только это устройство),
git переключается на credential.helper store. Доступ к репозиторию
проверяется сразу же.

### Чтобы ассистент сам публиковал обновления в ваш репозиторий

Если хотите, чтобы я публиковал новые версии прямо в ваш приватный
репозиторий (а вы на телефоне просто делали `start.sh`), пришлите мне
три вещи:

1. **ваш username на GitHub** (например `vasya`);
2. **имя приватного репозитория** (например `doomsday-bot`);
3. **fine-grained personal access token** — создаётся так:
   - GitHub → Settings → Developer settings → Personal access tokens →
     **Fine-grained tokens** → Generate new token;
   - Repository access: **Only select repositories** → выбрать `doomsday-bot`;
   - Permissions → Repository permissions → **Contents: Read and write**
     (остальные не нужны);
   - Expiration: 90 дней или меньше;
   - сгенерировать и скопировать токен (начинается с `github_pat_`).

Безопасность: токен даёт доступ только к содержимому этого одного репо,
отозвать можно в любой момент на той же странице (Delete). Не публикуйте
его нигде, кроме личного сообщения мне. Помните: в репо лежит ваш
`config.json` с api_id/api_hash — репозиторий должен оставаться PRIVATE.

## 13. История версий

- **1.3.0** — ГОТОВЫЙ API ИГРЫ + стартёр + логи: (1) встроенный пресет Doomsday
  Firebase callable — ребут через `rebootProduction` и полный скан состояния
  через `initUser` без какой-либо настройки (протокол реверс-инженерен из
  web-приложения: auth = сырой tgWebAppData, session = hash; свежая подпись
  получается через Telethon на каждом проходе); (2) `doomsday start` / `stop` —
  стартёр перенесён в python (git-обновление, переустановка при смене версии,
  wake-lock, сервисы sv или фоновые процессы с pid-файлами, контрольный проход
  cron; start.sh стал тонкой обёрткой); (3) `doomsday logs-push` — буфер логов:
  logs/ и reports/ не синхронизируются, выгрузка по команде в отдельную ветку
  `logs` (main не затрагивается), локальная копия чистится после отправки;
  (4) `doomsday git-auth` — сохранение PAT для git без пароля; (5) discover
  умеет находить Firebase-конфиг в JS и проверять рабочий эндпоинт (/syncTime)
  с самофиксом tma.base_url; (6) панель/сводка показывают дедлайн цикла
  производства (passiveFarm.endsAt); уведомление «требуется ребут» при
  истечении цикла; (7) таблица ёмкостей складов игры (lib/game_data.py) для
  точных процентов заполнения.
